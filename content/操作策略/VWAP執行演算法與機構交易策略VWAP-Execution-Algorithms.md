# VWAP 執行演算法與機構交易策略 VWAP Execution Algorithms

> 機構買 10,000 張不是一次下單——VWAP/TWAP/IS 演算法把大單拆成小單，像拼圖一樣慢慢組裝，不讓市場發現意圖。

## 核心概念

VWAP 執行演算法是機構投資者（避險基金、共同基金、主權基金）用來執行大額交易的核心工具。核心問題是：**如何在不衝擊市場價格的情況下，買入或賣出大量股票？**

如果一個機構要買 10,000 張台積電，直接下一筆大單會：
1. 瞬間吃掉五檔報價，成交價遠高於當前價格
2. 其他交易者發現大買盤進場，立刻提高賣價
3. 機構最終的平均買入成本遠高於原本的市場價格

VWAP 演算法的解法是：**把大單拆成幾百筆小單，分散在整天執行，讓每筆成交價盡量貼近當日 VWAP**。

## 三大主流執行演算法

### 1. VWAP（Volume-Weighted Average Price）

**原理**：根據歷史成交量分佈模式，在量大的時段多買、量小的時段少買，讓執行均價貼近 VWAP。

**計算邏輯**：
```
VWAP = Σ(Typical Price × Volume) / Σ(Volume)

Typical Price = (High + Low + Close) / 3
```

**實務操作**：
- 分析過去 20 天的日內成交量分佈（U型、L型等）
- 開盤和收盤量最大（佔全天 60-70%），中盤量最小
- 演算法按此比例分配子單：開盤多下、中盤少下、收盤多下
- 目標：執行均價 ≤ 當日 VWAP（買方）或 ≥ VWAP（賣方）

**適用場景**：
- 佔日均量 < 10% 的小型委託
- 交易量大且流動性好的標的
- 不需要緊急執行的大單

### 2. TWAP（Time-Weighted Average Price）

**原理**：把交易日等分為若干時段，每個時段執行相同數量的子單，不考慮成交量分佈。

**操作邏輯**：
- 假設要買 10,000 張，交易時間 5 小時（300 分鐘）
- 每 5 分鐘下 167 張（10000/60）
- 不論量大量小，時間到就下單
- 目標：執行均價接近當日時間加權平均價

**適用場景**：
- 日內成交量分佈不規律的標的
- 擔心 VWAP 在量小時段滑價過大
- 需要最小化市場衝擊而非追求最佳價格

### 3. IS（Implementation Shortfall）

**原理**：在「決策時刻的價格」和「最終執行均價」之間最小化差距，同時平衡兩個矛盾目標——**價格風險**（拖越久越可能碰到不利價格）和**市場衝擊**（下越大越推動價格）。

**操作邏輯**：
- 演算法動態調整執行速度
- 價格朝有利方向移動時 → 加速執行（怕機會消失）
- 價格朝不利方向移動時 → 減速等待
- 前段執行較快（降低價格風險），後段逐漸收尾（降低衝擊）
- 常用「front-loaded」策略：前 30% 時間執行 50-60% 的量

**適用場景**：
- 需要緊急但又要控制成本的大單
- 對執行品質要求極高的機構
- 佔日均量 > 10% 的大型委託

## VWAP 在台股的實戰意義

### 散戶如何利用 VWAP

**1. 判斷機構意圖**
- 價格持續在 VWAP 上方 → 機構淨買入，多方主導
- 價格持續在 VWAP 下方 → 機構淨賣出，空方主導
- 尾盤拉回 VWAP 附近 → 機構在收盤前執行，可能是 VWAP 演算法的收盤段

**2. 識別演算法執行足跡**
- 特定時間（如 9:00-9:30、13:00-13:30）出現規律的小單買入 → 可能是 VWAP 演算法在執行
- 盤中量縮但特定價位持續有小單消化 → 可能是 IS 演算法在低調執行
- 尾盤突然放量 → VWAP 演算法的收盤段，機構在趕進度

**3. 判斷自己的執行品質**
- 散戶買入價 < 當日 VWAP → 買在平均之下，執行品質良好
- 散戶買入價 > 當日 VWAP → 買在平均之上，可能追高了
- 詳見 [[技術分析/VWAP成交量加權均價]] 和 [[技術分析/VWAP偏差與機構執行足跡VWAP-Deviation-Institutional-Footprint]]

### 台股盤中 VWAP 的觀察重點

**開盤（9:00-9:30）**：
- 佔全天量 15-25%
- VWAP 執行演算法最大量段之一
- 價格與 VWAP 的偏離設定當日基調

**中盤（10:00-12:30）**：
- 量最小，VWAP 演算法減速
- 價格如果遠離 VWAP，可能是真實方向（非演算法推動）
- 突然放量且偏離 VWAP → 可能有大單非演算法執行

**收盤（13:00-13:30）**：
- 佔全天量 20-30%
- VWAP 演算法的「趕工段」
- 價格拉回 VWAP = 機構在收尾
- 價格遠離 VWAP = 真實趨勢強勁或突發消息

## VWAP vs MVWAP（Moving VWAP）

- **VWAP**：每個交易日重新計算，從開盤累積到收盤，是日內指標
- **MVWAP**：將每日 VWAP 當成數據點，用移動平均計算跨日 VWAP，適合跨日趨勢判斷
- VWAP 更平滑、MVWAP 反應更快但雜訊更多
- 詳見 [[技術分析/VWAP成交量加權均價]]

## 進階：VWAP 的自我實現預言

VWAP 有一個有趣的特性——**自我實現（self-fulfilling）**：

1. 大量機構用 VWAP 演算法執行
2. 他們的執行讓價格自然趨向 VWAP
3. 其他交易者觀察到價格回歸 VWAP，認為 VWAP 是「磁吸線」
4. 更多人在 VWAP 附近設定止損和目標價
5. VWAP 的支撐壓力效果更強
6. 進一步強化機構使用 VWAP 演算法的信心

**這就是為什麼 VWAP 不只是一個指標——它是整個市場的博弈框架。**

## 優缺點

**VWAP 演算法的優點：**
- 標準化程度高，容易評估執行品質
- 適合流動性好的大型股
- 不需要複雜的預測模型

**VWAP 演算法的缺點：**
- 落後指標，基於歷史成交量模式，遇到異常日會失靈
- 只在日內有效，跨日不適用
- 當自身大單佔市場量 > 15% 時，自身就是市場，VWAP 失去意義
- 強趨勢日中，VWAP 執行會錯失有利價格

**IS 演算法的優點：**
- 動態調整，適應市場變化
- 直接最小化執行成本
- 適合大單和緊急執行

**IS 演算法的缺點：**
- 需要複雜的預測模型
- 對數據品質要求高
- 參數調整更困難
