# 執行演算法 VWAP 與 TWAP

> 法人拆大單分批進出的背後邏輯——VWAP 追蹤市場均價、TWAP 時間均勻分布，目標都是最小化衝擊成本。

## 核心概念

### 為什麼需要執行演算法

當法人要買進數十億的個股，若一次性下單會嚴重衝擊市場價格（買進導致價格越買越高）。執行演算法（Execution Algorithms）把大單拆成小單，在一定時間內分批執行，讓成交均價盡量貼近市場自然價格。

### VWAP（Volume-Weighted Average Price）

VWAP 是最常用的執行演算法。核心邏輯：**在成交量大的時段多買，在成交量小的時段少買**，讓執行均價貼近當日的成交量加權均價。

- 計算：VWAP = Σ(成交價 × 成交量) ÷ Σ(成交量)
- 執行策略：依歷史成交量分布型態（U型或W型）分配每個時段的下單量
- 台股典型量能分布：開盤 9:00-9:15 量大、盤中量縮、收盤 13:00-13:30 量增
- 目標：執行均價 ≤ VWAP（買進）或 ≥ VWAP（賣出）

### TWAP（Time-Weighted Average Price）

TWAP 是最簡單的執行演算法。核心邏輯：**把大單均勻分布在時間軸上**，不考慮成交量分布。

- 執行策略：把總量除以時間區間數，每個時間區間執行固定量
- 適用場景：成交量分布不規則、或不想被市場看出下單模式時
- 缺點：在量小的時段仍會下單，衝擊成本可能較高

### 其他常見執行演算法

| 演算法 | 核心邏輯 | 適用場景 |
|--------|---------|---------|
| VWAP | 追蹤成交量加權均價 | 一般大單執行 |
| TWAP | 時間均勻分布 | 避免被市場看出意圖 |
| Implementation Shortfall | 最小化執行落差 | 緊迫需要完成的大單 |
| POV（Percent of Volume） | 佔當日成交量固定比例 | 流動性較差的標的 |
| IS（Implementation Shortfall） | 平衡衝擊成本與機會成本 | 需要快速完成的機構大單 |

## 實戰應用

### 1. 散戶為什麼要看懂

散戶不需要用執行演算法，但必須看懂法人在做什麼：
- **盤中突然出現連續小單買進** → 可能是 VWAP 執行中的法人買盤
- **特定時段量增但價格不動** → 可能是 TWAP 分批執行中的法人賣盤
- **開盤和收盤量大但盤中量縮** → 符合 VWAP 的 U 型量能分布，法人正在分批進出

### 2. 結合 VWAP 技術指標判讀

[[技術分析/VWAP成交量加權均價]] 是日內多空分界線。當法人用 VWAP 演算法執行時，他們的成交均價會貼近 VWAP 線：
- 價格在 VWAP 之上 → 法人買盤強於賣盤
- 價格在 VWAP 之下 → 法人賣盤強於買盤
- 法人執行完畢後價格回歸自然供需

### 3. 與 [[技術分析/內外盤比與五檔報價判讀InOut-Disk-Ratio-and-Order-Book]] 結合

法人分批執行時會在五檔報價留下足跡：
- 內盤連續小單 → 賣方急著賣（可能是 TWAP 賣出）
- 外盤連續小單 → 買方急著買（可能是 VWAP 買進）
- 拆單越細越難察覺，但持續觀察整日內外盤比可推斷法人方向

### 4. 與 [[風險管理/市場微結構與流動性定價Market-Microstructure-and-Liquidity-Pricing]] 結合

執行演算法本身就是市場微結構的一部分：
- 大單分批進出 = 法人透過演算法減少對流動性的衝擊
- 散戶若在法人執行區間反向操作，等於對抗一個有耐心的資金流

## 注意事項

- **散戶用不到但必須懂**：了解執行演算法不是為了使用，而是為了看懂盤中資金流向
- **不是萬能的**：遭遇突發事件時，VWAP/TWAP 的執行效果會大打折扣，法人也可能暫停執行
- **滑價仍存在**：分批執行減少衝擊但不消除滑價，參考 [[風險管理/滑價與交易執行風險]]
- **被偵測的風險**：市場上有偵測演算法執行的工具（如暗池偵測器），對手可能利用此資訊
- **台股的特殊性**：台股法人佔比相對美股低，執行演算法的影響力不如美股明顯，但外資大單仍是核心觀察對象
